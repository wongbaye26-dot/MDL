# v3.5.2 发布说明（2026-11-03）

本轮针对用户反馈的三个问题 + 一个新功能需求：

1. 播放器播放没有内嵌封面的本地音乐时没有专辑封面（应「本地封面优先，没有就联网获取」）
2. 音乐工具「缺封面的歌曲」统计为 0（实际很多），补封面一直不成功；并要求支持**批量刮削标签并写入保存**
3. 本地音乐列表显示不全，退出/重进后又正常

---

## 1. 播放器 / 列表封面链路：本地优先 → 网络兜底

**根因**
- 扫描会把 MediaStore 的 `content://media/external/audio/albumart/<id>` 写进 `meta.picUrl`。
  这个地址在**没有封面**的专辑上也会生成，图片加载必然失败。
- 旧逻辑把它当成「有封面」，于是播放器不再联网兜底 → 播放页一直黑/占位；
  列表同样拿这个坏地址渲染；音乐工具也据此统计成「全部都有封面」（见问题 2）。

**修复**
- `src/core/localMusic/cover.ts`
  - `isCoverUsable()` 不再信任任何 `content://`（尤其 albumart）：只认 http(s)、真实存在的本地文件、能抽到的内嵌封面；
  - `readEmbeddedCover()` 统一「私有目录按路径 / 公共目录按 SAF contentUri 抽取」，并缓存结果；
  - `fetchNetworkCover()` 改成 kw→tx→wy 多音源搜索，按歌名/歌手归一化打分（不再无脑取第一条），单源 8s 超时，只缓存成功结果；
  - `resolveLocalCover()` 统一入口：内嵌封面 → 曲库可用地址 → 网络缓存 →（允许时）联网。
- `src/core/music/local.ts`：本地歌曲取封面改为「本地优先，没有就联网找一张并写回曲库」，
  其它音源兜底路径也会把结果写回曲库，下次播放/列表直接用。
- `src/core/player/playInfo.ts`：播放器初始封面不再直接塞 albumart content:// 地址（避免先黑一块再等网络）。

**验收**
- 真机播放原无封面歌曲（如《江湖之间》）播放页出现专辑封面；
- 曲库里原本无封面的 26 首 FLAC 在补封面后重新读取文件，`PICTURE` 块（type 6）均已存在；
- 列表/首页「最近播放」中对应歌曲封面同步显示。

## 2. 音乐工具：统计修准 + 补封面真正成功 + 批量刮削标签（新功能）

**根因**
- 统计口径错：把 albumart `content://` 当成有效封面 → 233 首全部算「有封面」。
- 补封面流程只写文件/只改一处：不重新统计、不写回曲库、写入失败没有降级，看起来就是「一直不成功」。

**修复 / 新增**
- 统计改为「能不能真的显示」：`meta.picUrl` 是 http 或存在的本地文件 → 有；否则抽文件内嵌封面，抽到即写回曲库（自愈）；都没有才算缺失。
- 补封面：内嵌 → 联网搜索 → 下载图片（校验 ≥1KB，避免把错误页写进音频）→ 按 `contentUri → 真实路径 → 反查 contentUri` 写入音频文件（SAF 目录可写）→ 重新抽取并写回曲库；文件不允许改写时降级为「仅曲库记录网络封面」。汇总：本地封面 / 网络封面 / 仅曲库 / 未找到；支持进度、防重入。
- **新增「标签刮削」**：
  - 先扫描出标签可补全的歌（缺歌手 / 缺专辑 / 歌名里混着歌手 / 歌名来自文件名），显示数量与 30 条预览；
  - 逐首联网搜索最佳匹配（歌名必须对上，本地有歌手时歌手也必须对上，专辑/时长加分；占位歌手 `未知歌手/<unknown>` 特殊处理）；
  - 把 title/artist/album 写入音频文件（FLAC 额外有纯 JS 兜底写入，失败自动回滚，不会写坏文件），同时写回曲库；缺封面时顺手记录网络封面；
  - 支持进度、百分比、运行中「停止」（保留已完成结果）、完成 toast + 小结，完成后自动重新统计。
- `src/utils/flacTag.ts` 加固：纯 JS FLAC 写标签/封面改为「写临时文件 → 原文件备份 → 临时文件补位 → 删备份」，失败自动还原；只换封面时保留原标签，只改标签时保留原封面。
- 「补封面」「标签刮削」两个批量任务互斥，避免同时改写同一批文件。

**验收**
- 真机：统计从 0 变为 27（与实际无内嵌封面数量一致）；执行补封面后 27 → 0，文件内封面与列表封面均更新。
- 刮削匹配与 FLAC 写入有离线用例覆盖（歌名/歌手不匹配拒绝、只写标签保留封面、只换封面保留标签、音频帧不变、失败回滚等）。

## 3. 本地音乐列表显示不全 / 不刷新

**根因（引用 + 时序）**
- core 的 `cachedList` 是可变模块级数组，`getLocalMusicList()` 和 `localMusicUpdated` 事件都把**同一个数组引用**交给页面；
- 两段式扫描在补标签阶段**原地改数组**（`list[index] = ...`）并原地 `sort()`，页面 state 被 core 隔空修改却收不到通知；
- 扫描结束事件传的还是同一引用 → `setList(同一个引用)` 被 React bail out，`rows` 的 useMemo 也不重算 → 列表永久停在半成品；
- 重新挂载页面（退出重进 / 重启）会重新读缓存，于是「退出一下又可以了」。

**修复**
- core：对外/事件统一传副本；半成品只给本地音乐页做「首次扫描边扫边出歌」（本地订阅、800ms 节流、不重排），**完整扫完才**替换 `cachedList` 并持久化；扫描失败/中断保留上一次完整列表；单首坏文件不再中断整次扫描。
- 页面：所有 `setList` 使用新数组副本；处理「慢一步的缓存读取覆盖新数据」「扫描中挂载显示半成品」「重扫打断完整列表」三个时序；扫描失败落回完整列表。
- FlatList：初始批次 = `min(行数, 600)`，避开本工程 VirtualizedList「只渲染初始批次、滚动不补」的已知坑；233 首可从头滚到尾，上千首封顶 600 交由虚拟化。

**验收**
- 本地音乐 233 首从头滚到尾连续、无空白；切五个页签、切列表/卡片视图后行数不丢；
- 扫描完成后页面当场更新为新列表（无需重进）。

## 升级注意

- 覆盖安装请用 arm64 包（versionCode 更高）；universal 包 versionCode 是裸号，低于已装版本，只能全新安装。
- 补封面/刮削会实际改写音频文件（写入封面与标签）；公共目录若不允许写，只会更新曲库并提示「仅曲库」。
