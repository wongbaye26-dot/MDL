03问题清单

按严重度排序。P0 = 阻断或数据风险；P1 = 用户可感知的功能缺陷；P2 = 兼容/健壮性；P3 = 工程化。

级别问题证据与影响
P0 本次审计未发现阻断性问题 核心链路（启动、扫描、播放、下载、设置）均可用
P1 新旧两套播放器并存 screens/PlayDetail/ 2813 行旧 lx-music 播放器仍在注册（lxm.PlayDetailScreen）， 且「基本设置 → 启动后打开播放详情页」开关（player.startupPushPlayDetailScreen）打开后， 启动会 push 旧播放器，与新的飞牛风格播放器完全两套 UI。零代码复用。
P1 抽屉菜单「本地音乐」无文字 DrawerNav.tsx:114 调 t('nav_local')，但三个语言包都没有该键， getMessage() 对缺失键返回 '' → 只显示图标没有文字。本次已修（zh-cn/zh-tw/en-us 各补 1 行）。
P1 本地音乐没有列表/卡片切换 「支持列表/卡片样式」只覆盖了在线列表（OnlineList + 歌单详情），本地音乐自建列表未接
P1 在线播放仍可能随机等 2–6 秒 core/player/player.ts:79 const time = getRandom(2, 6)： 音源限流时进入 delayRetry，用户看到「正在获取链接，X 秒后重试」。 本地音乐已不走这条路，但在线歌曲仍会。
P1 无内嵌封面的歌只有图标 列表/播放器都退化成主题色底 + 音符图标，缺少「首字母」占位（此前提过但未确认实施）
P2 SAF 写入用了 API 26 才有的截断模式 DirectoryPickerModule.copyToTree 原用 openOutputStream(uri,"wt")， 但 minSdkVersion = 21 → Android 5–7 上下载完成却保存失败。 本次已修：改为「先删同名文档再 createDocument + "w"」，全程 API 21 可用。
P2 文件 IO 层完全没有类型 react-native-file-system 的 package.json 声明 types: lib/typescript/src/index.d.ts，但该文件不存在 → utils/fs.ts 与 localMediaMetadata.ts 共 6 个 TS2307， 整个文件系统层裸奔（这是最容易出运行时问题的一层）。
P2 getSavePath 缓存竞态 core/download/index.ts:354/360/365 eslint require-atomic-updates ×3： cachedSavePath 在 await 之后基于旧值赋值，并发下载时可能指向已被判定不可用的目录。
P2 SAF 授权被撤销后无提示 用户清理存储/重装后 treeUri 失效，只有下一次下载时报「目标目录不可写」，扫描则静默 0 首
P2 大目录扫描会丢标签 collectPublicDir 的 metaBudget = 500，超过 500 首后剩余文件只有文件名，无歌手/封面/采样率
P2 挖孔补偿是几何 hack CutoutCompensator 用「窗口宽 − 布局宽」负 margin 顶回去。主题 / MainActivity / RNN 三条正路都试过无效， 属于 RN 0.73 + RNN 7.39 + targetSdk 29 组合下的已知妥协；换机型需重新验证。
P3 零测试 全仓 0 个 *.test.* / __tests__，所有回归靠真机手点
P3 4 个核心原生依赖是本地 fork react-native-track-player@2.1.2（2021 年）、react-native-background-timer、 react-native-file-system、react-native-local-media-metadata 全部指向 file:../vendor/*。RNTP 还额外打了 updateNowPlayingTitles/isCached 等自定义方法 —— 升级等于重做移植。
P3 依赖靠 postinstall 打补丁 dependencies-patch.js 直接改 node_modules 里的 build.gradle（AGP 8 namespace）， 重装依赖若脚本没跑就构建失败
P3 类型与 lint 欠账 tsc 32 错 / 18 文件；eslint 81 错 / 7 警告 / 30 文件 （37 × no-unsafe-argument、25 × quote-props、5 × exhaustive-deps）
P3 调试输出未清理 106 处活跃 console.log（另有 216 处已注释），release 包里同样在打日志
P3 产物归档失控 dist/ 累积 133 个 APK / 3.0 GB（v2.0.0 → v3.5.0）； EMO-v3.5.0 只有 21:05 的 arm64 一份，最新 22:07 的构建（含本次修复）未归档，且缺 universal
P3 签名密钥只存本机 keystore.properties 已 gitignore（安全没问题），但密钥无异地备份 → 丢失后老用户无法覆盖升级，只能卸载重装
